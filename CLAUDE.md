# CLAUDE.md

Behavioral guidelines to reduce common LLM coding mistakes. Merge with project-specific instructions as needed.

**Tradeoff:** These guidelines bias toward caution over speed. For trivial tasks, use judgment.

## 1. Think Before Coding

**Don't assume. Don't hide confusion. Surface tradeoffs.**

Before implementing:
- State your assumptions explicitly. If uncertain, ask.
- If multiple interpretations exist, present them - don't pick silently.
- If a simpler approach exists, say so. Push back when warranted.
- If something is unclear, stop. Name what's confusing. Ask.

## 2. Simplicity First

**Minimum code that solves the problem. Nothing speculative.**

- No features beyond what was asked.
- No abstractions for single-use code.
- No "flexibility" or "configurability" that wasn't requested.
- No error handling for impossible scenarios.
- If you write 200 lines and it could be 50, rewrite it.

Ask yourself: "Would a senior engineer say this is overcomplicated?" If yes, simplify.

## 3. Surgical Changes

**Touch only what you must. Clean up only your own mess.**

When editing existing code:
- Don't "improve" adjacent code, comments, or formatting.
- Don't refactor things that aren't broken.
- Match existing style, even if you'd do it differently.
- If you notice unrelated dead code, mention it - don't delete it.

When your changes create orphans:
- Remove imports/variables/functions that YOUR changes made unused.
- Don't remove pre-existing dead code unless asked.

The test: Every changed line should trace directly to the user's request.

## 4. Goal-Driven Execution

**Define success criteria. Loop until verified.**

Transform tasks into verifiable goals:
- "Add validation" → "Write tests for invalid inputs, then make them pass"
- "Fix the bug" → "Write a test that reproduces it, then make it pass"
- "Refactor X" → "Ensure tests pass before and after"

For multi-step tasks, state a brief plan:
```
1. [Step] → verify: [check]
2. [Step] → verify: [check]
3. [Step] → verify: [check]
```

Strong success criteria let you loop independently. Weak criteria ("make it work") require constant clarification.

---

**These guidelines are working if:** fewer unnecessary changes in diffs, fewer rewrites due to overcomplication, and clarifying questions come before implementation rather than after mistakes.

# Project: Carolina Premier Lawn & Tree Services website

Live site: https://carolinapremierservices.org (hosted on Netlify, auto-deploys from this repo's `claude/andrej-karpathy-skills-0gvsbk` branch, which is also the default branch). A copy also builds on GitHub Pages at https://jezreelacencioo-sys.github.io/ryco-landscaping/ and points its canonical URLs at the domain.

## How the site is built
- Static HTML generated by Python. **Never hand-edit the generated `*.html` files**; edit the sources and rebuild.
- Rebuild: `python3 _build/build.py` (main site, ~76 pages + 404, sitemap.xml, robots.txt).
- Sources:
  - `_build/content.py`: business facts (`BUSINESS`, `SITE`), towns, guides, home FAQs, `REVIEWS`, `PROJECTS`, `SOCIAL`.
  - `_build/services.py`: the 11 services (name, copy, items, FAQs, image; optional `steps`).
  - `_build/combos.py`: unique copy for each service-in-town page, keyed `(service_slug, town_slug)`. Services without combos (sod, drainage, gutter, Christmas lights only partly) link to the main service page instead.
  - `_build/build.py`: page templates, structured data (LocalBusiness, Service, FAQ, Article, Breadcrumb), header/footer.
  - `styles.css`, `main.js`: shared design and behavior.
- Design concepts and color mockups live in `/concepts/` (built by `python3 _build/concepts/build_all.py`, noindex). Not part of the live design.

## Design (approved by the owner)
- "Premier Mix" style: deep green `#0a4d24`, near-black, lime `#86cf45`, accent "All Green" `#a6e35f` (CSS `--accent*` variables; yellow was rejected).
- Fonts: Barlow Condensed (headlines), Lilita One (playful accent words, class `hl`), Nunito (body).
- Header logo: straight, no box (owner disliked the boxed/tilted version).
- Real job photos are in `images/work/` (from the owner's previous site). Fencing and Christmas still use illustrations because there are no real photos (fence photo was wood; owner installs vinyl).

## Business facts (keep consistent everywhere)
- Name: Carolina Premier Lawn & Tree Services LLC. Phone (984) 381-8731. Email carolinalawnservice1@gmail.com. Apex, NC.
- Hours: Mon–Fri 7am–7pm, Sat 7am–5pm. 100% insured. 5.0 on Google, 25 reviews.
- Towns: Apex, Cary, Holly Springs, Fuquay-Varina, Morrisville, southwest Raleigh.
- Christmas lighting: company supplies, installs, maintains, removes and stores the lights. **Do not publish pricing, bulb specs (C9, spacing) or wiring/hardware details** on the site.

## Integrations
- Contact page uses the embedded **Jobber** online request form (IDs in `_build/build.py`: `JOBBER_ID`, `JOBBER_FORM_URL`). Form fields and booking hours are changed in Jobber, not in this repo.
- Netlify's free plan injects a "Powered by Netlify" badge that covers the mobile "Text Us" button; fix by upgrading Netlify or moving DNS to GitHub Pages. Do not hide it with CSS.

## Before pushing
- Rebuild, then check every page at desktop and phone width (no horizontal overflow, no broken links/images, valid JSON-LD, one h1, titles ≤ 65 chars, descriptions 70–165 chars).
